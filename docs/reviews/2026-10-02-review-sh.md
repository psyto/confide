Verdict: the retry is safe, but the observer and documentation overclaim, and the RPC privacy claim is currently false.

1. `go()` retry

Safe in every current `go` caller. Each passes an already serialized, signed transaction as one argument; `go` resends exactly those bytes, hence the same signature. A Solana transaction with that signature cannot be applied twice. This covers issuance, swaps, testbed, borrow, seizure, and the proof loops.

The one gap is coverage, not safety: the allocation in [`issue-e2e.sh`](/Users/hiroyusai/src/confide/scripts/issue-e2e.sh:404) calls `send` directly, so it does not get the new retry. Its on-chain-refusal path also intentionally uses its own `landed()` sender.

2. Observer: not sufficient for its claims

High-severity correctness issue. It verifies that cited transactions exist, have the expected failure code/success, two signature slots, and Token-2022 top-level instructions. It does not establish that those transactions are the claimed approval/allocation/trade.

- Approval only proves a cited transaction succeeded; it does not bind its instruction, mint, or target account to the event. See [`observe-run.py`](/Users/hiroyusai/src/confide/scripts/observe-run.py:123).
- Settlement does not compare instruction accounts/mints against the event’s parties or public-account rows, nor establish that the two transfers are the claimed legs. It cannot verify confidential amounts without keys, but it can and should verify account/mint/instruction binding. See [`observe-run.py`](/Users/hiroyusai/src/confide/scripts/observe-run.py:130).
- Top-level program IDs are not enough for “no Confide program inside the trade.” It must inspect `meta.innerInstructions` too; otherwise a top-level program could invoke Confide by CPI.
- The mint/account state is read only at observation time, not at the transaction’s slot. A gate could have differed during the claimed flow.
- The short control is entirely trusted from JSONL: any `pre_sign_check` event becomes an `ok` row with no chain evidence. A short run can pass with only `run`, that event, and `done`. See [`observe-run.py`](/Users/hiroyusai/src/confide/scripts/observe-run.py:120).
- Normal-mode coverage requires only two named refusals, any settlement, any public row, and `done`; it does not require mint rows, issuer approval, the half-signed control, pre-sign check, or both acts. See [`observe-run.py`](/Users/hiroyusai/src/confide/scripts/observe-run.py:162).
- It reuses the runner’s `RPC`, so it is a separate keyless process, not an independent data source.

The offline tests pass, but they test the implemented predicates, not these omitted bindings.

3. Sweep and SOL

The current role-name glob catches the funded wallets in today’s default flow (`issuer`, `investor`, `buyer`), but is brittle: a renamed/new role, nested key, or key outside those exact paths is missed. See [`review.sh`](/Users/hiroyusai/src/confide/scripts/review.sh:84).

It returns only spendable wallet SOL. It does not reclaim rent in mints, token accounts, proof-context accounts, or lookup tables. It also hides failed transfers, still exits successfully, and reports the starting wallet balance as “returned” even though the transfer fee reduces it. The final EXIT trap retries on ordinary exits, but does not make an incomplete sweep visible or protect against hard termination/power loss.

`NEED_SOL=2.3` looks reasonable for the current default: the normal flow first funds three wallets with 0.7 SOL each, leaving roughly 0.2 SOL headroom. It is a threshold, not a guaranteed net-cost estimate; rent and fees are version/workload dependent.

4. RPC leak

Confirmed. The endpoint is written unredacted into run-directory files:

- [`issue-e2e.sh`](/Users/hiroyusai/src/confide/scripts/issue-e2e.sh:86) writes `issuer.yml` and `investor.yml`.
- [`issue-e2e.sh`](/Users/hiroyusai/src/confide/scripts/issue-e2e.sh:470) writes `buyer.yml`.

Thus `$RUN/normal/*.yml` and `$RUN/short/*.yml` contain `json_rpc_url: <private endpoint>`. This directly contradicts the script comment and claimed zero-occurrence grep. Terminal/run-log piping is redacted, and the script itself does not enable `set -x`; however, redaction is only exact-string replacement and does not protect artifacts or externally enabled tracing.

5. README/docs wording

The new block overclaims.

- “checked by something that was not in it” implies more independence than exists: it is part of the same repository, invoked by the runner, consumes its event log, and uses the same RPC.
- “re-reads every signature and account” should be qualified to “re-reads the cited transaction/account objects it is implemented to check.” It cannot verify the local short-check claim.
- “returns all but about 0.15” should be historical, not a guarantee, because rent is not reclaimed and sweep failures are silent.
- “About eight minutes” is fair for the documented 488-second run, but should say it is a recent run and cold builds/RPC outages can take longer.
- [`REVIEW-RUNS.md`](/Users/hiroyusai/src/confide/docs/cwf-2026/REVIEW-RUNS.md:6) says receipts are copied verbatim, but the generated receipt title is omitted.
